# APIアクセス解析

Filma APIの利用状況をPlatform管理者が確認するための画面です。APIキーをURLとヘッダーのどちらで送信しているか、利用組織・APIユーザー・エンドポイント・送信元の傾向を確認できます。

## 画面URLと権限

- URL: `/filmaplatform/apiaccess/`
- Platform管理者だけがアクセスできます
- `/filmaadmin/` には公開しません
- 一覧・詳細の参照はPlatform操作履歴へ記録されます

## 記録対象

`/filmaapi/`配下へのアクセスを記録します。ただし、APIキーが提示されていない次の高頻度リクエストは、既存の再生アクセス解析との重複を避けるため除外します。

- プレイヤー
- DASH・HLSマニフェスト
- DRMライセンス
- ダウンロード

これらのリクエストでも、`X-Api-Key`または`api_key`パラメーターが提示された場合は、APIキーの利用実態を把握するため記録します。

## 確認できる内容

- 期間内のアクセス、成功、拒否、エラー件数
- X-Api-Key、URLパラメーター、両方、APIキーなしの送信方法別件数
- URLパラメーターでAPIキーを送信した件数
- Referer / Originがない件数
- 組織別、APIユーザー・キー別、エンドポイント別、送信元IP識別子別のランキング
- HTTPメソッド、認証方式、APIキー送信方法、HTTP状態
- Refererホスト、Originホスト、User-Agent
- 認証主体の会員、Mediafile、FilmaFile、視聴プラン、期限付きURL
- APIルートから判定した操作対象種別、組織内で確認済みの対象ID、要求された対象ID
- ルート別の許可リストを通過した補助IDとページング値
- 個別アクセスの詳細

APIユーザーIDはログ記録時の値も保持するため、APIユーザーを物理削除した後もユーザー別の利用履歴を分離して確認できます。現存する組織・APIユーザーは現在の名称を表示し、物理削除済みの場合だけログ記録時の名称を表示します。

初期表示は直近7日です。24時間、7日、30日、90日または366日以内の任意期間を指定できます。

## APIキーと送信元IPの取扱い

APIアクセスログには、APIキーと送信元IPの値そのものは保存しません。障害発生時は、弊社管理画面からだけ参照できる社内向け技術ログへ送信元IPが記録される場合があります。

- APIキー識別子: アプリケーション秘密鍵を使ったHMAC-SHA256
- 送信元IP識別子: 組織秘密鍵、組織を特定できない場合はアプリケーション秘密鍵を使ったHMAC-SHA256

送信元IP識別子は期間をまたいで同一送信元の傾向を確認できますが、元のIPアドレスへ戻すことはできません。IP制限を設定する場合は、この識別子から推測せず、API利用者へ実際の送信元IP/CIDRを確認してください。

APIキーを含み得るクエリ文字列は保存しません。リクエストパスはクエリを除いた`path_info`だけを保存し、Referer / Originはホスト名だけを保存します。

## リクエスト対象情報の取扱い

APIアクセスログでは、認証した主体とAPI操作の対象を分けて記録します。例えばAPIユーザーが`/filmaapi/customers/:id`を呼び出した場合、APIユーザーは認証主体、パスの会員IDは操作対象です。会員JWTの場合は、署名と組織を確認できた会員を認証主体として記録します。

パスの数値IDはルートごとに意味を判定します。

- `/filmaapi/storage/:id`: FilmaFile
- `/filmaapi/storage/metadata/:id`: FilmaFile
- `/filmaapi/storage/folders/:id`: フォルダー
- `/filmaapi/player/:id`、`/dash/:id`、`/hls/:id`、`/download/:id`: Mediafile
- `/filmaapi/customers/:id`、`/customers/entitlements/:id`: 会員
- `/filmaapi/entitlements/:id`: 視聴権

「確認済み操作対象ID」は、認証された組織内に対象が存在する場合だけ保存します。「要求された操作対象ID」は、APIパスまたはルート別に許可したパラメーターで指定された値であり、存在しないIDを含む場合があります。両者を分けることで、別組織の対象情報をログへ紐付けずに、不正形式や存在しないIDへの要求も調査できます。

補助的な要求情報は、対象ルートで意味が固定された次の項目だけを`request_details`へ保存します。

- `folder_id`、`item_id`、`sku_id`、`shop_id`、`mediafile_id`
- `page`、`per_page`
- 会員への視聴権付与で使用する固定列挙値`scope_type`（`item`、`sku`、`shop`のみ）

IDとページング値は、各ルートのAPI本体と同じ変換・範囲補正を行い、APIが実際に使用した値を記録します。入力された未加工の文字列や数値は保存しません。

認証前に401または403となる場合など、アクセスログがJSON本文を直接参照するときは、本文抽出を64KiBまでに制限します。本文が上限を超える場合は本文由来の項目を抽出せず、APIレスポンスを変更せずに、`request_details`へ次の固定情報を記録します。パスから判定できる操作対象は通常どおり記録します。

```json
{
  "body_extraction": {
    "status": "skipped",
    "reason": "size_limit_exceeded",
    "limit_bytes": 65536
  }
}
```

リクエスト本文やクエリ全体は保存しません。JWT、APIキー、パスワード、メールアドレス、氏名、メモ、検索文字列、タグ、任意メタデータは`request_details`の保存対象外です。Mediafile等の確認済みIDは、認証・認可コンテキストを優先し、要求値から補完する場合も組織内の関連を確認します。

追加列を利用するコードの反映前に、次のDDLをデータベースへ適用してください。

```sh
psql データベース名 -f filma_doc/membership/ddl/014_filma_api_access_log_request_details.sql
```

## 保存期間

保存対象期間は180日です。APIアクセスを記録する各アプリケーションプロセスが1日1回、180日を超えたログを削除します。APIアクセスがない期間は削除処理も行われず、次回のAPIアクセス記録時に削除されます。必要に応じて、運用処理から次のモデルメソッドを実行して手動削除することもできます。

```ruby
FilmaApiAccessLog.purge_expired!
```

## 既存のアクセス解析との違い

`/filmaplatform/accesslog/`はストリーミングとダウンロード入口の利用状況を確認する画面です。APIアクセス解析はAPIキーの利用経路や管理API等の利用状況を確認する画面であり、集計目的とログテーブルを分離しています。

APIキーを使った再生入口は両方へ記録される場合がありますが、それぞれ「再生利用」と「APIキー利用」という異なる目的で集計します。
